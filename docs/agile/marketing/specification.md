## Architecture and contracts

New Marketing domain and NestJS module with separate DTOs/mappers, use cases, repository and media processor ports. Reuse JWT principal resolution, AgentRepository, representation ListingGate, existing PostgreSQL transaction scope, MediaStorage and browser FileReader/HttpClient. Extend storage factory with optional private bucket configuration while retaining existing defaults; do not make tour media private accidentally. Dedicated private marketing-media bucket and actor scoped marketing_media, marketing_drafts and ordered marketing_draft_media tables. RLS uses the existing app user context and actual Agent identity, minimum application role grants, no anonymous table rights.

GET /agent/marketing returns draft/media summaries and authorized property choices, including approved listing photos only after accepted active representation, verified/public Agent and canEditListing checks. No price, exact private location or Owner account secrets. Agent may prepare private generic drafts without a property; listing linked drafts and source photos recheck the representation gate on read/write. Source photo references are stored as trusted listing photo IDs/URLs selected from current authorized listing data, never arbitrary client remote URLs. Revoked listing access makes the linked draft action required and prevents its media preview until reauthorized or detached.

GET/POST /agent/marketing/drafts; GET/PUT/DELETE /drafts/:id; POST /drafts/:id/duplicate. Version required for edits; stale version returns 409. Draft media links refer only to owned READY assets; max 10 media per draft. Caption max 2200, title max120. Internal future lifecycle DRAFT, READY_FOR_REVIEW, APPROVED, PUBLISHING, PUBLISHED, FAILED, CANCELLED, PARTIALLY_PUBLISHED, ACTION_REQUIRED. Phase 1 writes DRAFT/READY_FOR_REVIEW only; ready requires caption and media. Individual destination publication outcomes are a future separate model, not a client writable published flag.

GET/POST /agent/marketing/media; GET /media/:id/read; DELETE /media/:id. Existing API accepts base64 JSON with a global 40 MiB ceiling. Validate 8 MiB image/12 MiB MP4 before decoding, canonical base64, allowed magic and reported MIME. Sharp normalizes image orientation, strips metadata, refuses over 20M pixels, emits JPEG. MP4 container signature accepted for private storage/preview only; no codec conversion or external eligibility claim. Media PENDING becomes READY only after storage succeeds; failure records FAILED with cleanup. Quota 100 objects/256 MiB per Agent includes unresolved PENDING/FAILED. Private URLs expire in120 seconds, not stored as permanent links. Delete checks draft references before removing storage; referenced media returns409. Bounded storage, no video processing queues or paid libraries. Schema not available returns safe service unavailable, not fake empty success.
