# Security review evidence and limits

Resolved or improved: F01 strict public mobile configuration/no project fallback/encoded service-role rejection; F02 bounded webhook streams; F03 stale Owner session response protection/private-state reset; F04 cache cleanup recovery; F08 HTTP timeouts. Reviewed backend identity code verifies signature/issuer/audience with JWKS and loads capabilities/membership server-side; editable user_metadata supplies display names only. Inspected manual-review verification adapter never marks ML Kit evidence automatically verified. No production biometrics/provider success was fabricated.

API supply chain (F06): compatible versions pinned to Nest 11.2.7, Fastify 5.12.7, Sharp 0.35.5 and Vitest 4.1.12. Nest's older nested Fastify was explicitly overridden to the same compatible Fastify 5 patch as the direct dependency. A fresh npm lock resolution plus clean install was necessary because in-place npm install/update retained the invalid old nested version despite the override. Final npm tree deduplicates to 5.12.7 and npm audit reports **zero API vulnerabilities at this run**. This is dependency-advisory coverage, not proof of exploit absence. Owner Web/Flutter dependency security review is still incomplete.

Supporting advisories: [Nest adapter absolute-target middleware bypass](https://github.com/advisories/GHSA-9c5c-9qcx-q35q), [Sharp/librsvg memory vulnerability](https://github.com/advisories/GHSA-wq5f-xc86-pv6w). Applicability varies by deployment; no successful exploit against this application was claimed.

F07 remains unresolved: Android release signing uses the debug key. No signing keys were changed. Real production distribution must wait for a reviewed release-signing setup. No live credentials were rotated or copied into artifacts.

`scripts/check-public-config.py` rejects unexpected Flutter config names and scans mobile public source/config plus API/Postman exports for selected private key signatures and service-role JWTs. Passed. This intentionally does **not** certify a whole-repository/history secret audit. Postman templates contain blank credentials; production mutation guards are present. Test reports omit response payloads. Real `.env.local` values were not printed or exported.

Database checks use a new isolated PostgreSQL cluster with synthetic seed data, never an existing shared database. The script stops its own server, preserves its server log and removes only its marked disposable cluster directory. Full DB test results are in 06-test-results. Backend capture ownership, expiry, submission/approval, invoice overpayment, payment replay and organization isolation tests are included in the existing integration suite; this does not prove deployed Supabase RLS/storage settings match local schema/stubs.

Remaining security acceptance: detailed review of all pending files, deployed auth/session revocation guarantees, full RLS and storage-policy reconciliation, authorized/foreign-role HTTP fixtures, provider callback behavior, retention operation monitoring, rate-limit/abuse review, dependency/security scanning outside the API, and protected release environment configuration. F10's inferred schemas and success examples are not security enforcement.

F12 financial integrity: reproduced cross-organization allocation, unsettled payment allocation, source-budget overspend and concurrent invoice overpayment. The repository now locks source then target and validates both budgets within one transaction. The additive `20261022131003_guard_payment_allocations.sql` migration independently checks organization, state and budgets for raw inserts. Tests verify invoker security, fixed search path and no public execution privilege. No live exploit is asserted.

This migration was tested only on disposable databases. Existing historical allocations were not backfilled or reconciled, and deployment remains pending. Synthetic database stubs grant broad privileges to the test role; these results do not establish least-privilege production grants or deployed Supabase policy parity. Payment/refund lifecycle interactions beyond the inspected allocation path still require review.

F13 rejects unsafe integer centavo values in the shared primitive and inspected invoice conversions. F17 prevents previously cleared search history from reappearing after a stale disk read. These narrow corrections do not establish full monetary precision or private-cache lifecycle coverage across every repository.
